# Руководство по внесению вклада / Contributing Guide

Спасибо, что хотите внести вклад в **Project-IdealPromt**! 🎉

Thank you for wanting to contribute to **Project-IdealPromt**! 🎉

## 🌟 Способы внести вклад / Ways to Contribute

### 1. Поделиться опытом / Share Experience
- Опишите ваш кейс работы с промтами
- Используйте шаблон из `/templates/experience-template.md`
- Сохраните в папку `/experiences/`

### 2. Добавить наблюдение / Add Observation
- Опишите интересный паттерн или находку
- Используйте шаблон из `/templates/observation-template.md`
- Сохраните в папку `/observations/`

### 3. Поделиться примером / Share Example
- Добавьте эффективный промт
- Используйте шаблон из `/templates/prompt-example-template.md`
- Сохраните в папку `/examples/`

### 4. Улучшить документацию / Improve Documentation
- Исправьте ошибки
- Дополните существующие руководства
- Улучшите примеры

### 5. Предложить идеи / Suggest Ideas
- Создайте Issue с вашими предложениями
- Обсудите новые направления развития

## 📝 Процесс внесения вклада / Contribution Process

### Шаг 1: Fork репозитория
```bash
# Нажмите кнопку "Fork" на GitHub
# Клонируйте ваш fork
git clone https://github.com/ваш-username/Project-IdealPromt.git
cd Project-IdealPromt
```

### Шаг 2: Создайте ветку
```bash
git checkout -b feature/your-contribution-name
```

### Шаг 3: Внесите изменения
- Следуйте структуре проекта
- Используйте предоставленные шаблоны
- Пишите на русском и/или английском

### Шаг 4: Зафиксируйте изменения
```bash
git add .
git commit -m "feat: добавлено [описание вашего вклада]"
```

Используйте понятные commit messages:
- `feat:` — новая функциональность
- `docs:` — изменения в документации
- `fix:` — исправление ошибок
- `style:` — форматирование

### Шаг 5: Push и создайте Pull Request
```bash
git push origin feature/your-contribution-name
```

Затем создайте Pull Request на GitHub.

## ✅ Чек-лист перед отправкой / Pre-submission Checklist

- [ ] Содержимое следует структуре проекта
- [ ] Используются предоставленные шаблоны
- [ ] Тексты четкие и понятные
- [ ] Добавлены примеры (где применимо)
- [ ] Проверена орфография
- [ ] Указаны теги и категории
- [ ] Файлы названы описательно

## 📋 Стандарты качества / Quality Standards

### Для опыта и наблюдений / For Experiences and Observations

✅ **Делать / Do:**
- Будьте конкретны и детальны
- Приводите реальные примеры
- Объясняйте контекст
- Указывайте результаты
- Делитесь выводами

❌ **Не делать / Don't:**
- Расплывчатые описания
- Отсутствие примеров
- Только теория без практики
- Копирование чужого контента без указания источника

### Для примеров промтов / For Prompt Examples

✅ **Делать / Do:**
- Тестируйте промт перед публикацией
- Указывайте назначение
- Приводите пример вывода
- Объясняйте параметры
- Описывайте варианты использования

❌ **Не делать / Don't:**
- Непроверенные промты
- Отсутствие описания
- Слишком специфичные без объяснения
- Промты, которые могут быть вредными

## 🎨 Стиль и форматирование / Style and Formatting

```markdown
## Уровень 2 / Level 2
### Уровень 3 / Level 3
```

### Блоки кода / Code Blocks
````markdown
```язык
ваш код здесь
```
````

### Списки / Lists
```markdown

- Элемент 2
  - Подэлемент

1. Нумерованный 1
2. Нумерованный 2
```

- 💡 — идеи и советы / ideas and tips
- ⚠️ — предупреждения / warnings
- ✅ — рекомендации / recommendations
- ❌ — не рекомендуется / not recommended
- 📊 — результаты и метрики / results and metrics
- 🔍 — детали и анализ / details and analysis

## 🌍 Язык / Language

Приветствуются материалы на русском и английском языках. Идеально — билингвальный контент.

Materials in Russian and English are welcome. Bilingual content is ideal.

## 🤝 Код поведения / Code of Conduct

- Будьте уважительны к другим участникам
- Конструктивная критика приветствуется
- Помогайте новичкам
- Делитесь знаниями открыто

## 💬 Вопросы и поддержка / Questions and Support

Если у вас есть вопросы:
1. Проверьте существующие Issues
2. Создайте новый Issue с вопросом
3. Обсудите в Pull Request

- В истории коммитов
- В списке контрибьюторов
