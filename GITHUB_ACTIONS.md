# GitHub Actions - Автоматическая сборка

Этот проект настроен на автоматическую сборку .exe файла через GitHub Actions.

## 🚀 Как это работает

### Автоматическая сборка

Сборка .exe запускается автоматически при:
- **Push в ветку main** - создаёт артефакт для тестирования
- **Создании тега** (например, `v1.0.0`) - создаёт GitHub Release
- **Pull Request** - проверяет, что сборка работает

### Ручной запуск

Вы можете запустить сборку вручную:
1. Перейдите на вкладку **Actions** в репозитории
2. Выберите **Build Windows Executable**
3. Нажмите **Run workflow**
4. Выберите ветку и нажмите **Run workflow**

## 📦 Где найти готовый .exe

### Вариант 1: Скачать артефакт после сборки

1. Откройте вкладку **Actions** в GitHub
2. Выберите последний успешный workflow
3. Прокрутите вниз до секции **Artifacts**
4. Скачайте `LetterGenerator-Windows.zip`
5. Распакуйте архив - внутри будет `LetterGenerator.exe`

### Вариант 2: Создать Release

Чтобы создать официальный релиз:

```bash
# Создайте и отправьте тег
git tag v1.0.0
git push origin v1.0.0
```

После этого:
1. GitHub Actions автоматически соберёт .exe
2. Создаст новый Release на вкладке **Releases**
3. Прикрепит `LetterGenerator.exe` к релизу
4. Пользователи смогут скачать его напрямую

## 🏗️ Что происходит при сборке

1. ✅ Checkout кода
2. ✅ Установка Python 3.12
3. ✅ Установка зависимостей из `requirements.txt`
4. ✅ Установка PyInstaller
5. ✅ Создание .exe файла
6. ✅ Упаковка в архив с документацией
7. ✅ Загрузка артефакта (доступен 90 дней)
8. ✅ Создание Release (если был создан тег)

## 📋 Структура релиза

После сборки в архиве будут:
- `LetterGenerator.exe` - исполняемый файл
- `INSTALL.txt` - инструкция по установке
- `README.md` - документация

## 🔧 Настройка версий

Для создания новой версии:

```bash
# Patch версия (1.0.0 -> 1.0.1)
git tag v1.0.1
git push origin v1.0.1

# Minor версия (1.0.1 -> 1.1.0)
git tag v1.1.0
git push origin v1.1.0

# Major версия (1.1.0 -> 2.0.0)
git tag v2.0.0
git push origin v2.0.0
```

## ⚡ Быстрый старт

### Первый релиз:

```bash
# 1. Убедитесь, что код работает
git add .
git commit -m "Готов к первому релизу"
git push

# 2. Создайте тег первой версии
git tag v1.0.0
git push origin v1.0.0

# 3. Подождите ~5-10 минут
# 4. Проверьте вкладку Releases - там будет ваш .exe
```

## 🐛 Устранение неполадок

**Сборка не запускается:**
- Убедитесь, что файл `.github/workflows/build-exe.yml` закоммичен
- Проверьте вкладку Actions - она должна быть включена в настройках репозитория

**Сборка падает с ошибкой:**
- Откройте лог сборки в Actions
- Проверьте, что все файлы присутствуют в репозитории
- Убедитесь, что `requirements.txt` содержит все зависимости

**Не создаётся Release:**
- Убедитесь, что тег начинается с `v` (например, `v1.0.0`)
- Проверьте настройки репозитория - Actions должен иметь права на создание релизов

## 📊 Мониторинг
