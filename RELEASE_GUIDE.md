# 🚀 Руководство по созданию релиза

## Быстрый старт: Создайте первый .exe за 5 минут!

### Шаг 1: Создайте тег версии

```bash
# В терминале VS Code выполните:
git tag v1.0.0
git push origin v1.0.0
```

### Шаг 2: Дождитесь сборки

1. Перейдите на GitHub: https://github.com/Kogl-B/Project-IdealPromt
2. Откройте вкладку **Actions**
3. Увидите запущенный workflow "Build Windows Executable"
4. Дождитесь зелёной галочки (займёт ~5-10 минут)

### Шаг 3: Скачайте готовый .exe

**Вариант A: Из Releases (рекомендуется)**
1. Перейдите на вкладку **Releases**: https://github.com/Kogl-B/Project-IdealPromt/releases
2. Увидите новый релиз `v1.0.0`
3. Скачайте `LetterGenerator.exe`
4. Готово! Можете распространять этот файл

**Вариант B: Из Artifacts (для тестирования)**
1. На странице Actions откройте завершённый workflow
2. Прокрутите вниз до секции "Artifacts"
3. Скачайте `LetterGenerator-Windows.zip`
4. Распакуйте архив

## 📋 Создание последующих версий

### Семантическое версионирование

Формат: `vМАЖОР.МИНОР.ПАТЧ` (например, `v1.2.3`)

- **ПАТЧ** (`v1.0.0` → `v1.0.1`) - Исправления багов
- **МИНОР** (`v1.0.1` → `v1.1.0`) - Новые функции (обратно совместимые)
- **МАЖОР** (`v1.1.0` → `v2.0.0`) - Крупные изменения (несовместимые)

### Примеры

```bash
# Исправили баг
git tag v1.0.1 -m "Исправлена ошибка при чтении пустых ячеек"
git push origin v1.0.1

# Добавили новую функцию
git tag v1.1.0 -m "Добавлена поддержка PDF экспорта"
git push origin v1.1.0

# Крупное обновление
git tag v2.0.0 -m "Полностью переработанный интерфейс"
git push origin v2.0.0
```

## 📊 Мониторинг сборок

### Просмотр логов

1. Actions → выберите workflow
2. Нажмите на задачу (например, "build")
3. Разверните шаг для просмотра деталей

### Статус сборки

Badge в README показывает текущий статус:
- ✅ Зелёный - всё работает
- ❌ Красный - сборка сломана
- 🟡 Жёлтый - сборка в процессе

## 🐛 Устранение неполадок

### Сборка падает с ошибкой

**Проблема**: "ModuleNotFoundError"
```bash
# Решение: Добавьте модуль в requirements.txt
echo "missing-module==1.0.0" >> requirements.txt
git add requirements.txt
git commit -m "Добавлен пропущенный модуль"
git push
```

**Проблема**: "File not found"
```bash
# Решение: Убедитесь, что файл закоммичен
git add missing-file.py
git commit -m "Добавлен пропущенный файл"
git push
```

### Release не создаётся

**Причина**: Тег должен начинаться с `v`
```bash
# ❌ Неправильно
git tag 1.0.0

# ✅ Правильно
git tag v1.0.0
```

### Artifact не появляется

**Причина**: Нужно дождаться завершения workflow
- Обычно занимает 5-10 минут
- Проверьте вкладку Actions - должна быть зелёная галочка

## 💡 Советы

### 1. Автоматизация changelog

Добавьте описание изменений при создании тега:

```bash
git tag v1.0.1 -m "
Исправления:
- Исправлена ошибка при пустых ячейках
- Улучшена обработка ошибок

Улучшения:
- Ускорена обработка больших файлов
"
git push origin v1.0.1
```

### 2. Pre-release версии

Для тестовых версий используйте суффиксы:

```bash
git tag v1.1.0-beta.1
git tag v1.1.0-rc.1  # release candidate
```

### 3. Удаление ошибочного тега

```bash
# Локально
git tag -d v1.0.0

# На GitHub
git push origin :refs/tags/v1.0.0
```
